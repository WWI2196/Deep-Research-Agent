# AGENTS.md

This file guides AI agents working on the **Deep Research Agent** codebase.

## Project Overview

A multi-agent deep research system that plans, searches, reads, reflects, and synthesizes high-quality cited reports.

- **Backend**: Python FastAPI + LangGraph async state machine + SQLite (WAL) + Chroma
- **Frontend**: Vanilla JavaScript SPA (no framework), served as static files
- **Search**: Self-hosted SearXNG (70+ engines, no API key)
- **RAG**: Chroma vector store + bm25s keyword search + RRF fusion
- **Pipeline**: `init → plan → split → subagents → reflection → synthesize → cite → END`

## Agent Architecture

### Core Pipeline (LangGraph StateGraph)

7 async nodes in `src/backend/graph.py`:

1. **init** — Initialize research state
2. **plan** — Generate structured research plan (dimensions + keywords + source types)
3. **split** — Break plan into 3-8 parallel subtasks
4. **subagents** — Concurrent subagent execution (web search + document library RAG)
5. **reflection** — Quantitative per-dimension scoring; gaps trigger re-search
6. **synthesize** — Single-pass LLM synthesis with truncation recovery + parallel section deepening
7. **cite** — Rule-based citation numbering + URL liveness verification

### State (`ResearchState` in `src/backend/models.py`)

TypedDict maintaining:
- `query`, `research_plan` (structured dict), `subtasks`, `subagent_reports`
- `sources`, `iteration_count`, `cited_report`, `memory`
- `query_cache`, `synthesis_retry_count`, `context_compress_retries`, `keep_tool_results`
- `document_collections` — selected RAG collections for this run
- `_subtask_report_map: dict[str, str]` — subtask_id → report (deduplication for reflection re-runs)

### Key Modules

| Module | Purpose |
|--------|---------|
| `server.py` | FastAPI app, 23 REST endpoints + SSE streaming; all sync DB calls wrapped with `asyncio.to_thread` |
| `graph.py` | LangGraph pipeline definition, 7 async nodes; persistence calls parallelized via `asyncio.gather` |
| `planning.py` | `generate_research_plan`, `split_into_subtasks` |
| `subagent.py` | Subagent orchestration: query gen, search, evaluate (parallel batches), extract, report |
| `synthesis.py` | `synthesize_report`, `add_citations`, parallel thin-section deepening |
| `search.py` | SearXNG (async aiohttp pool) + Crawl4AI browser pool + trafilatura fast path |
| `llm.py` | Unified async `chat()` with per-role provider routing; messages shallow-copy to prevent mutation |
| `config.py` | Config loading: env var > `~/.deep-research/config.yaml` > default |
| `persistence.py` | SQLite I/O (8 tables) with thread-local connection pool + WAL mode |
| `document_store.py` | Chroma + bm25s + RRF hybrid retrieval; singleton pattern; parallel collection/vector/BM25 queries |
| `tracing.py` | Structured tracing via `contextvars`, log levels |

### Agent Roles (LLM Routing)

7 roles, each can use different provider+model:
- `planner`, `splitter`, `subagent`, `evaluator`, `coordinator`, `reflection`, `citation`

Providers: mimo, openai, anthropic, gemini, deepseek, openrouter

### Subagent Flow (`run_subagent`)

1. **Rules-based query generation** (keywords × source_type modifiers)
2. **Parallel search**: SearXNG + document library hybrid retrieval
3. **Batch evaluation**: All batches in parallel via `asyncio.gather` (not sequential)
4. **Content extraction**: trafilatura fast path (~0.2s) → Crawl4AI browser pool (~4s) → Chrome fallback
5. **Evidence building**: Keep top evidence, compress if needed
6. **Report writing**: With `[src: url]` inline citations
7. **Validation**: Retry on empty report or missing citations

### Content Extraction Pipeline

Three-tier extraction in `search.py:extract_async`:
1. **trafilatura** (fast, ~0.2s) — handles 80-90% of static HTML pages
2. **Crawl4AI browser pool** (shared singleton, ~4s) — for JS-rendered pages
3. **Chrome fallback** (standalone, ~6s) — if pool browser fails

Connection pools:
- **Crawl4AI**: Singleton `AsyncWebCrawler` with `asyncio.Semaphore(4)` for concurrency control
- **aiohttp**: `TCPConnector(limit=30, limit_per_host=10)` for SearXNG + PDF downloads
- **SQLite**: Thread-local connections with WAL mode + 8MB cache

### Synthesis & Citations

- **synthesize_report**: Single-pass with max_tokens=30000, 6-round truncation continuation, failure summary retry
- **_deepen_thin_sections**: All thin sections expanded in parallel via `asyncio.gather` (max 3 concurrent LLM calls)
- **add_citations**: Rule-based parsing of `[src: url]` → `[^n]`, concurrent URL liveness check (8-way parallel)
- Auto-strips duplicate References/Sources sections generated by LLM

## Key Conventions

- **Async everywhere**: All I/O uses `asyncio.to_thread` (SQLite, trafilatura); direct async for aiohttp/search
- **Parallelism**: Subagents via `asyncio.gather`, batch evaluations via `asyncio.gather`, persistence via `asyncio.gather`
- **Connection pooling**: Crawl4AI browser pool, aiohttp HTTP pool, SQLite thread-local pool — do NOT create new connections per call
- **State immutability**: Prefer creating new state objects over mutation
- **LLM messages**: Always shallow-copy messages list before modification (date prefix injection)
- **Citations**: Always use `[src: url]` format in subagent reports; synthesis must not generate References/Sources sections
- **Config preservation**: `save_config()` must preserve unmanaged sections (providers, search)
- **Tracing**: Use `trace()` / `trace_llm_call()` for observability; `run_id` propagated via `contextvars`
- **Error handling**: Self-heal JSON parse failures by feeding error back to LLM; fallback strategies for empty results

## Frontend Architecture

- **Pages**: Home, Dashboard, Report, History, Library, Settings
- **State**: `createStore()` event-driven state management
- **API**: HTTP + SSE streaming (`api.js`)
- **Router**: `app.js` handles page lifecycle + cleanup
- **New components**: `library.js` (document management), `log-viewer.js` (debug viewer)

## Document Library (RAG)

- **Upload**: PDF/DOCX/TXT/MD/HTML → async parse → chunk → embed → index
- **Search**: Chroma vector + bm25s keyword → RRF fusion → Top-K chunks
- **Integration**: Subagent stage runs web search and document search in parallel
- **Quota**: `source_type_quotas` prevents document sources from crowding out web sources
- **Singleton**: Use `get_document_store()` to get shared instance (avoids re-creating ChromaClient)

## Performance Characteristics

Typical research task (4 subagents, 2 iterations):
- **Total time**: ~30 minutes
- **LLM calls**: ~100 (94 subagent + 7 coordinator + others)
- **Sources collected**: ~130
- **Report length**: ~25,000 chars

Bottleneck breakdown:
- **LLM latency**: 90% of total time (subagent calls avg 18s, synthesis calls avg 77s)
- **Content extraction**: ~5% (trafilatura fast path absorbs most static pages)
- **Search**: ~3% (SearXNG async with connection pool)
- **Persistence**: ~2% (SQLite WAL + thread-local pool)
